# 03 - Git & GitHub

---

# 1. Objective

This document explains how Git and GitHub were used in the PlacementPro AI Platform.

The goal is to maintain version control, track project history, collaborate efficiently, and safely store source code in a remote repository.

---

# 2. What is Git?

Git is a distributed version control system (DVCS) used to track changes in source code.

It allows developers to:

- Track every code change
- Restore previous versions
- Work on new features safely
- Collaborate with other developers
- Maintain complete project history

Git works locally on the developer's machine.

---

# 3. What is GitHub?

GitHub is a cloud-based platform that hosts Git repositories.

GitHub provides:

- Remote repository hosting
- Team collaboration
- Pull Requests
- Issue Tracking
- Code Reviews
- CI/CD Integration
- Project Documentation

Git manages version history.

GitHub stores and shares Git repositories.

---

# 4. Why Git is Important

Without Git:

- Code can be lost.
- Mistakes are difficult to undo.
- Team collaboration becomes difficult.
- No version history exists.

With Git:

- Every change is recorded.
- Previous versions can be restored.
- Multiple developers can work simultaneously.
- Code is backed up remotely.

# 6. Git Repository Initialization

The project repository was initialized from the project root.

```bash
git init
```

Purpose:

Creates a hidden `.git` directory that allows Git to start tracking the project.

---

# 7. Checking Repository Status

```bash
git status
```

Purpose:

Displays:

- Current branch
- Modified files
- New files
- Deleted files
- Files ready for commit

This is one of the most frequently used Git commands.

---

# 8. Staging Files

```bash
git add .
```

Purpose:

Moves all project changes to the staging area.

The staging area acts as a preparation area before creating a commit.

---

# 9. Creating a Commit

```bash
git commit -m "Initial Spring Boot project setup"
```

Purpose:

Creates a snapshot of the project at the current point in time.

A commit message should clearly describe the changes.

Examples:

```
Initial Spring Boot project setup

Create User entity

Add UserRepository

Implement registration service
```

---

# 10. Renaming the Branch

Git initially created:

```
master
```

The project was renamed to:

```
main
```

Command:

```bash
git branch -M main
```

Reason:

Modern Git repositories use **main** as the default branch.

---

# 11. Connecting Remote Repository

```bash
git remote add origin https://github.com/username/repository.git
```

Purpose:

Connects the local Git repository with GitHub.

Verify connection:

```bash
git remote -v
```

---

# 12. Pushing Code to GitHub

```bash
git push -u origin main
```

Purpose:

Uploads the local commits to GitHub.

The `-u` option sets the upstream branch so future pushes only require:

```bash
git push
```

---

# 13. Folder Structure Strategy

The project follows this structure:

```
PlacementPro/

├── backend/
├── frontend/
├── docs/
├── README.md
└── .gitignore
```

This structure keeps backend, frontend, and documentation separate.

---

# 14. .gitignore

Purpose:

Ignore files that should never be committed.

Examples:

```
target/
.idea/
.vscode/
*.iml
HELP.md
```

Reason:

These files are machine-specific or generated automatically.

---

# 15. Why target/ is Ignored

The `target/` directory is generated by Maven.

It contains:

- Compiled classes
- Build artifacts
- Temporary files

Since Maven recreates it automatically, it should never be stored in Git.

---

# 16. Git Lifecycle

```
Working Directory

↓

Staging Area

↓

Local Repository

↓

Remote Repository
```

Explanation:

Working Directory

Your current project files.

↓

Staging Area

Prepared changes.

↓

Local Repository

Saved commit history.

↓

Remote Repository

GitHub backup and collaboration.

---

# 17. Best Practices

- Commit small changes frequently.
- Write meaningful commit messages.
- Never commit passwords or API keys.
- Keep `.gitignore` updated.
- Push code regularly.
- Keep documentation under version control.

---

# 18. Common Mistakes

## Initializing Git inside the wrong folder

Solution:

Run `git init` from the project root.

---

## Forgetting `.gitignore`

Result:

Generated files are uploaded to GitHub.

---

## Pushing sensitive information

Never upload:

- Database passwords
- API keys
- Secret tokens
- Environment variables

---

## Large commits

Instead of one huge commit, create multiple logical commits.
